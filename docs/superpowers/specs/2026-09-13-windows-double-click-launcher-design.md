# Windows 双击启动文件设计

## 目标

在项目文件夹根目录提供一个可双击的 Windows 启动文件，与现有的 macOS `启动 FIS.command` 对称，让 Windows 上的开发环境无需手动输入命令即可启动本地 Web 工具。

本功能**不是便携版**：它复用项目已配置好的 Python 3.12 虚拟环境，不打包解释器、依赖或安装包。真正的便携分发（PyInstaller 单文件夹）是独立的后续工作，2026-09-07 那份便携计划所引用的模块结构早已重组，需要重写后再执行。

## 交付物

- 文件名：`启动 FIS.bat`
- 位置：项目文件夹根目录
- 可从资源管理器双击运行

## 启动行为

1. 启动文件根据自身位置（`%~dp0`）定位项目根目录，不写死用户目录或 worktree 绝对路径。
2. 将控制台代码页切换为 UTF-8，确保中文提示不出现乱码。
3. 检查 `.venv\Scripts\python.exe` 是否存在。
4. 设置 `PYTHONPATH` 为项目内 `src`，切换工作目录到项目根目录，执行 `python -m fis`。
5. FIS 自动从 `8765–8775` 中选择第一个可用端口，并打开默认浏览器。
6. 如果已有健康实例，沿用现有单实例逻辑（Windows 上是命名互斥锁），仅打开已有页面。
7. 关闭最后一个 FIS 页面后，后台按照现有 30 秒宽限期自动退出。

## 错误处理

- 缺少 `.venv` 时，不尝试联网安装或修改环境；显示中文说明，提示重新配置开发环境，暂停窗口以便阅读，返回非零退出码。
- FIS 启动失败时保留程序原有中文错误信息，并把其退出码原样传出。
- 路径包含空格或中文时仍能正常启动。

## 与 macOS 版的差异

| 关注点 | macOS `.command` | Windows `.bat` |
| --- | --- | --- |
| 解释器路径 | `.venv/bin/python` | `.venv\Scripts\python.exe` |
| 中文输出 | 终端默认 UTF-8 | 需 `chcp 65001` |
| 自身目录 | `${0:A:h}` | `%~dp0`（含尾部反斜杠） |
| 退出码传递 | `exec` 替换进程 | `exit /b %ERRORLEVEL%` |
| 出错暂停 | 交互式时 `read` | `pause` |

## 两个 cmd 解析约束

1. **中文提示不能放进 `if (...)` 块。** cmd 会把括号块当作一个整体先行解析，其中的非 ASCII 字节可能在代码页生效前被错误处理。失败分支因此改走 `goto :missing_venv` 标签，让每一行中文都停留在语句层。
2. **文件必须保持 CRLF 行尾。** cmd 对纯 LF 的批处理行为不可靠。由于 git 会按 `core.autocrlf` 改写行尾，仓库加了 `.gitattributes`（`*.bat text eol=crlf`）保证任何机器检出后都是 CRLF；同一份规则也把 macOS 的 `.command` 钉在 LF，并把表格文件标记为二进制。

## 验证

本项目的开发机是 macOS，无法本地执行 `.bat`。验证因此分两层：

1. **跨平台静态检查**（随处可跑）：启动文件存在、使用 `%~dp0` 相对定位而非硬编码路径、指向项目虚拟环境、设置 `PYTHONPATH`、切换代码页、包含中文缺失环境提示。
2. **真实 Windows 执行**（仅在 Windows 上运行）：用替代 Python 程序验证传入的工作目录、`PYTHONPATH` 与参数正确；并验证缺少 `.venv` 时的错误分支。

第 2 层通过 GitHub Actions 的 `windows-latest` runner 执行。该 runner 同时让仓库中现有的 7 个 Windows-only 跳过用例（命名互斥锁、目录联接、目录句柄）首次获得真实平台覆盖——首轮 CI 可能因此暴露既有缺陷，这是预期收益而非回归。
