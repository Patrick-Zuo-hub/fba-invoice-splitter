# 2026-09-14：默认提货日与开船日的规则调整

## 状态

已实施。**待 PRD 补记** —— 见下方「与产品基线的关系」。

## 背景

`default_dates` 原先的行为是：

- 提货日期 = 最近的一个周四，**包含今天**（今天是周四则为今天）
- 开船日期 = 提货日期 + 7 天，即再下一个周四

使用中提出两点：开船日期应为周一而非周四；且今天若是周四，当周的截单已过，提货日不应落在今天。

## 决定

- **提货日期 = 严格晚于今天的第一个周四。** 今天若是周四，顺延至下周四。
- **开船日期 = 提货日期之后的第一个周一。**

```
今天 2026-09-14（周一） → 提货 09-17（周四），开船 09-21（周一）
今天 2026-09-17（周四） → 提货 09-24（周四），开船 09-28（周一）
今天 2026-09-18（周五） → 提货 09-24（周四），开船 09-28（周一）
```

两个日期都严格位于未来，不会出现默认值就是今天的情况。

## 为什么锚定提货日而非今天

「下下周一」按字面可以从今天起算，但那样会在周五至周日打开工具时把开船日排到提货日之前：9/11 周五提货日已滚到 9/17，而从今天起算的「下下周一」是 9/21 —— 看似仍然靠后，但只要提货日再往后滚一周就会倒置。

锚定提货日使「开船晚于提货」成为结构性保证，而不是依赖日期恰好排得开。测试对连续 400 天逐日验证了这一不变量。

## 实现说明

偏移量是算出来的而非写死的 +4：

```python
days_until_monday = (0 - delivery.weekday()) % 7 or 7
```

提货日目前恒为周四，因此结果恒为 +4。之所以不直接写 +4，是为了在提货日锚点将来变动时规则仍然成立；`or 7` 保证提货日若恰为周一时开船日严格靠后。

提货日一侧用的是同一个写法，`or 7` 正是让今天在今天是周四时被排除的那一段。

测试对连续 400 天逐日验证三条不变量：提货恒为周四、开船恒为周一、且 `今天 < 提货 < 开船`。
